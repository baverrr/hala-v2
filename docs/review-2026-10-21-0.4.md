# Review of 0.2.0–0.4.0, 2026-10-21 (before publishing 0.4.0)

Diff `b3622ef..` (after the first security review). Five read-only reviews ran in parallel:
a security review and pr-review-toolkit's code reviewer, silent-failure hunter, test analyzer
and comment analyzer. Every finding below was fixed; 454 tests pass, ruff and pyright clean.

## Security

| # | Severity | Issue | Fix |
|---|----------|-------|-----|
| S1 | Medium | `[x](file){rel=attachment}` (or `<a rel=attachment>` in HTML) made WeasyPrint embed any sibling file in the PDF; a document in `~` could attach `.ssh/…`. | `_confine` strips attributes from links; the WeasyPrint fetcher serves only real pictures and fonts; paths with a hidden component below the root are refused in both. |
| S2 | Medium | 7z picks the decoder by content: a bzip2 stream named `.zip` listed no sizes, a gzip one a forged size, so the zip-bomb check passed. | The listing's `Type` must match the extension and every entry must have a size; `7z x -t<type>`; the unpacker runs under `prlimit --fsize` and the result is measured. |
| S3 | Low/Med | PDF → pictures and Read QR rendered any number of huge pages; the editor rendered before checking pixels. | `pdf.check_render`: per-page pixel limit, 5000 pages, 20 gigapixels, estimated size vs free space, all before rendering; the editor checks the page size first. |
| S4 | Low | The .deb copied the working tree, so stray files could ship. | `build_deb.stray_files()` refuses untracked/ignored files under `hala/`. |
| S5 | Low | `note:` lines could carry terminal escape sequences from document link targets. | `jobs.clean_note` replaces control characters. |
| — | Low | `Job.params` (holding a PDF password) appeared in `repr(job)`. | `repr=False`. |

## Bugs and silent failures

- Unpacking tar/gz counted the space already written twice (refused archives over ~half the free space): free space is read once.
- qpdf's exit 3 (worked, with warnings) failed Compress, merge, split and metadata on slightly damaged PDFs: accepted, with a note; Compress falls back to Ghostscript if qpdf really fails.
- Unlock said "wrong password" for restricted-only PDFs when a password was typed: retries with an empty one.
- Compress changed formats and dropped tracks silently: notes for PNG/TIFF/BMP → JPG (transparency), lossless sound → M4A, video → MP4 with extra tracks left out; README and help text corrected.
- Saving an edited PDF to a vanished folder said "needs qpdf": now "can't save in …".
- Unknown encryption state (qpdf missing, timeout) was treated as "not encrypted": Unlock and the editor now say why they can't check.
- Pictures WeasyPrint couldn't load disappeared without a note; a broken WeasyPrint gave a traceback: both reported, and the DOCX/LibreOffice route is used as a fallback.
- Notes were lost in partly failed batches and capped at 3 silently: kept, logged, "…and N more".
- Sparse-file message said "left out" though the archive wasn't made: reworded.
- Phone zip folder errors crashed the send; network files on the clipboard gave the wrong message; wl-paste errors weren't logged: fixed.
- Hala's print stylesheet lost to pandoc's embedded styles (a WeasyPrint user stylesheet): pandoc's CSS is off for PDFs and `print.css` is injected as the last author style.
